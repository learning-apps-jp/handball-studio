# SO-Q Stats 記録入力フローの参照

確認日：2026-10-26（日本時間）。今回の優先対象は得点・失点・GKセーブの素早い入力と、アクション後の段階的な詳細入力。

## 根拠と範囲

[公式ガイド](https://stats.so-q.jp/guide)と[公式FAQ](https://stats.so-q.jp/faq)を再取得した。FAQは95問・2026-10-24更新のまま。以下は公式文章で確かめられた流れであり、ダイアログ内部を実際に完走した結果ではない。記録が保存されるタイミング、閉じる・戻るの挙動は、公式文章だけで断定しない。

公式サンプルの正確なURL： https://stats.so-q.jp/match?id=sample-match 。新しいブラウザでは、先に https://stats.so-q.jp/ を開いて初回案内を処理し、ホームの架空サンプルから入るのが確実。サンプルは当時11対5、40件のイベント。実データは使わない。

## 自チームの得点

1. 記録する選手のボタンを押す。選手未選択でもチーム記録として入力可能。
2. 「ゴール」を押す。
3. 9分割のゴールコースを選ぶ。
4. コート上のシュート位置を選ぶ。
5. 攻撃形態（速攻・クイックスタート・セットOF）は任意で付与できる。エンプティーは別属性として併用できる。

ガイド本文で明記される詳細入力順は「コース→コート位置」。シュート種類・攻撃形態が同じ画面にあるか別段階か、最後に明示的な保存ボタンがあるか、どの段階にスキップがあるかは本文では未確認。

## 自チームのシュート失敗

1. 原則として選手を先に選ぶ。
2. 「シュート×」を押す。
3. シュート結果、9コース、コート位置を記録できる。枠外の場合は上／左／右、ポスト・バーの区分も記録できる。
4. 形態は任意。

公式文章は得点と失敗をまとめてコース→位置と説明するが、「GKに止められた／枠外／ポスト等」の選択がコースの前後どちらにあるかまでは説明しない。枠外位置やポスト・バーは選ばずに記録可能。失敗から結果を選ぶ実際の分岐はサンプルで確認する必要がある。

## 相手シュート：自チームだけモード

| 結果 | 最初に押すもの | 帰属と注意 |
|---|---|---|
| 決められた | 守備行の「失点」 | 現在選択中の自チームGKに失点が付く。自チームのゴールではない。 |
| GKが止めた | 守備行の「セーブ」 | 自チームGKのセーブ。同じプレーを別途相手シュートとして重複入力しない。 |
| 外れた | 守備行の「枠外」 | GKセーブ率の分母に含めない。方向・ポスト・バーを省略可能。 |
| 相手7m | 「ペナ」 | 通常の自チーム7m成功／失敗と混同しない。結果の選択画面順は未確認。 |

失点・セーブでもゴール9分割とコート位置、相手の攻撃形態を付与できる。文章は各ダイアログの正確な並びや省略操作を列挙していない。

GK交代は上部の現GKを変更する。切替を忘れた場合は後から対象記録のGKを付け替えられる。得点の入力時に自チームGKを選び直す手順ではない。

## 相手シュート：両チームモード

- iPad横長では自チームと相手チームが左右に並ぶ。
- 相手の打者を選び、相手側の「ゴール」または「シュート×」を押す。
- 公式が具体例で示すセーブ手順は「相手側のシュート×→セーブ」。これだけで自チームGKのセーブへ自動計上。
- 両チームモードでは自チーム側の守備専用行（失点・セーブ・枠外・ペナ）と相手反則行を隠し、二重入力を防ぐ。
- 相手のGKも別に指定可能。自チームの得点・失敗から相手GK成績を導出する。

## 時刻の固定

- 詳細画面をすべて入力し終えた時刻を記録する方式ではない。
- 最初に押した瞬間を基準にする。
- 選手選択から15秒以内にアクションを押した場合は、選手を選択した時刻を使う。
- 15秒より後、または選手未選択なら、アクションを押した時刻を基準にする解釈となる。
- その後にコース・位置を選んで時計が進んでも、イベントの基準時刻は変えない。
- 前後半と時刻はログから後修正できる。

「15秒以内」は公式の表現。15秒ちょうどの厳密な実装（<=か丸めか）は内部実装未確認。独自版では15秒以内を含むものとして定義し、境界テストを用意する。

## 省略・取消・訂正

公式文章で確認済み：

- 選手未選択→チーム記録として保存できる。
- 攻撃形態は任意、ログから後付けもできる。
- 枠外方向・ポスト／バーなどの詳細は省略できる。
- 忙しい試合中は得点・セーブだけ記録し、動画を見て後補完する運用を案内。
- 直前イベントは「1つ戻す」で取消。過去の種類・選手・コース・時間の変更と削除も可能。

未確認：

- ダイアログの「戻る」が1段戻るか全閉じるか。
- ダイアログを閉じる・背景を押す・Escapeで、イベント自体を取消するか、入力済み情報だけ保存するか。
- コースと位置のそれぞれにスキップボタンがあるか。
- 最終位置タップで自動確定するか、別の保存ボタンを押すか。
- 前段階へ戻ったときの選択保持。
- アクション直後に暫定得点が変わるか、最後に変わるか。

## 親側のサンプル画面確認に渡すチェックリスト

1. サンプルで打者を選ぶ→ゴール。最初の画面の見出し・選択肢・省略を記録。
2. 最初の画面で安全に次へ進めるか確認し、コース→位置以外の段階の順を記録。
3. 画面上の取消・閉じるで確定前に撤退。得点・イベント件数が変化していないか確認。
4. 自チームだけモードへ切替えて守備の失点・セーブ画面を同様に確認。
5. シュート×でセーブ／枠外／ポスト・バーの分岐、戻り方を確認。
6. 端末は使い捨てサンプル環境で、既存利用者の保存データへ接続せず、共有コードは作らない。

独自版ではまずこの記録導線を優先し、アクションの意味が先に決まり、必要な詳細を順番に選べる画面へする。原画面の意匠ではなく操作機能を合わせ、時刻とGK帰属を入力開始時に固定する。確定前取消と保存後の1つ戻すは別の操作として検証する。

## サンプル実画面で確認した詳細（2026-10-26追記）

親エージェントが公式サンプルの画面をCUAで確認した。入力は確定前に取り消し、サンプルの40件・11対5が変化していないことを確認。原サービスのコード・画面画像を独自アプリへコピーしていない。参考画像は公開・配布しない。

### 得点：2段階

1. 打者を選んで「ゴール」を押すと、最初の詳細画面が開く。
2. **STEP 1：シュートの詳細とコース。** 同じ画面に任意属性と9コースが並ぶ。
   - 攻撃形態：速攻、クイックスタート、セット。
   - 独立した状況属性：エンプティー、リバウンド。
   - シュート種類：サイド、カットイン、ミドル、ポスト、ノーマーク。
   - 球種：ループ、スピン、バウンド、スカシ、速球、自由テキスト。
   - 9分割のコースはシューターから見た方向。画面の上下左右をGK視点へ反転して解釈しない。
3. コースを押すと **STEP 2：コート上のシュート位置** へ進む。
4. コートの位置を押すと記録される。「位置なしで記録」で位置を省略でき、「記録しない」で確定前取消できる。

したがって、「ゴールを押したら即保存して、詳細は後で別フォームへ入力する」流れとは異なる。任意属性とコースを一つ目の段階で選び、その後に位置で記録を完了する点が、操作上の中心となる。

### シュート失敗：最初の段階で結果を選ぶ

- STEP 1には結果の選択があり、枠外／セーブ／ブロックから選ぶ必要がある。
- 結果未選択の間は、コース選択とスキップの操作が無効。
- 枠外方向は左・上・右・左ポスト・バー・右ポストの6ボタン。
- 外れ方向を選ぶと位置の段階へ進む。
- 得点と同様、位置で完了する前に記録取消できる。

### 自チームのみのGK守備入力

- 「セーブ」を押すと同系統のSTEP 1が開くが、コースの問いはGKが止めた位置を選ぶ表現になる。
- 相手7mの「ペナ」では、先に失点／セーブ／枠外の3結果を選ぶ専用画面が開く。
- 7m結果選択後のすべての詳細遷移は今回の確定前観察で完走していないため、通常シュートと同じと断定しない。

### 独自版への反映と比較上の位置付け

Handball Studioの従来の即保存中心の入力から、標準のシュート入力を上記の2段階へ変更する作業を優先する。独自版ではイベントの時計・選手・GKを入力開始時に固定し、段階を戻っても値を保持すること、取消でスコア・イベントが増えないことを受入条件にする。「戻る」の厳密な挙動は独自版での改善仕様であり、今回確認していない原サービスの内部動作と同一とは説明しない。

冒頭の公式文章ベースの手順と未確認事項は調査履歴として残す。STEP 1／STEP 2の具体的な項目と確定条件については、この実画面確認の追記を優先する。
